# Project Archive — Freeze, Package, and Preserve the Complete Research Record

> **User request:** $ARGUMENTS

## ⚠️ CRITICAL RULES

1. **Archive output → `.research/archive/`** directory.
2. **Use research tools to read data** — `research_experiment(list)`, `research_claim(trace)`, etc.

---

## Prerequisites

- Submission is in terminal state (`accepted` / `rejected` / `closed`), OR the user explicitly requests archival
- Paper exists (may be `frozen` or `archived`)

## Output contract

- All research objects are in terminal states
- `.research/archive/` directory contains the complete archive package
- Experiment index, claim-evidence map, and exhibit provenance table are generated
- Reproducibility package is assembled
- AGENTS.md is updated as the final handoff brief
- Project state is set to `archive`

---

## DAG Template

```mermaid
graph LR
    load[Load Context] --> freeze_entities[Freeze Entities]
    freeze_entities --> generate_docs[Generate Documents]
    generate_docs --> verify[Verify Completeness]
    verify --> archive[Archive Package]
```

Nodes:
- `load` — Load project state, submission status, and all research objects
- `freeze_entities` — Archive paper, close submission, resolve all intermediate-state objects
- `generate_docs` — Create experiment index, claim-evidence map, exhibit provenance, reproducibility package, timeline summary
- `verify` — Confirm all objects are terminal, all archive documents are complete
- `archive` — Package into `.research/archive/`, write final handoff brief, set phase to archive

## Skill Checklist (v2.2)

### Must
- Read current state via `research_state(action="overview")` before acting
- Record decision rationale in journal via `research_journal(action="append", kind="decision_rationale", note="...")`
- When a human checkpoint is triggered, the system auto-generates a brief; use `research_checkpoint_brief(action="read")` to view it
- Use research tools to read data — `research_experiment(list)`, `research_claim(trace)`, etc.
- Verify all objects are in terminal states before generating archive documents

### Forbidden
- Do not archive without resolving intermediate-state objects (park, reject, stop, retract)
- Do not modify archived objects after the archive is sealed
- Do not skip the final handoff brief update to AGENTS.md

### Checkpoints
- all_entities_frozen
- archive_complete

## Context Refresh (Mandatory at Entry)

When re-entering this skill (new session or after context compaction):

1. **Load state** — `research_state(action="overview")` → get current phase, focus refs, active run
2. **Read phase run** — `research_state(action="read")` → inner loop state, attempts, stagnation
3. **Check wiki** — `research_wiki(action="query", query="archive completeness")` → relevant knowledge
4. **Review journal** — `research_journal(action="read", last=10)` → recent decisions and rationale
5. **Resume or pivot** — If `inner_loop.state === "evaluate"`, review progress metric and decide; if `"decide"`, check stagnation and choose iterate/pivot/promote

After refresh, write context recovery to the phase run:
```
research_state(action="brief", context_refresh={trigger: "session_resume", loaded: ["state","wiki","journal"], checked_skill_rules: true})
```

## Step 2: Freeze All Objects

### 2.1 Paper

```
research_paper(action="archive", id="paper_001")
```

### 2.2 Submission

If not already closed:
```
research_submission(action="close", id="sub_001", outcome="[accepted/rejected/closed]")
```

### 2.3 Verify all objects are in terminal states

```
research_idea(action="list")       // all should be: selected, parked, or rejected
research_plan(action="list")       // all should be: active, superseded, or cancelled
research_experiment(action="list") // all should be: completed, failed, invalidated, or stopped
research_claim(action="list")      // all should be: final, retracted, or weak
research_exhibit(action="list")    // all should be: approved, superseded, or dropped
```

Flag any objects still in intermediate states (e.g. `exploring` ideas, `draft` plans, `registered` experiments). Resolve them explicitly:
- Unfinished ideas → `park` or `reject`
- Unfinished plans → `cancel`
- Unstarted experiments → `stop`
- Unresolved claims → `retract` or `weaken`
- Unfinished exhibits → `drop`

## Special Cases

### Partial Archive (project paused, not concluded)

If the user wants to archive a project that hasn't reached submission:
- Freeze whatever exists at current quality
- Generate partial documents (e.g. experiment index without claim map if claims don't exist yet)
- State clearly in README.md that this is a partial archive
- Record the reason for pausing
- Set `research_state(action="advance", target_phase="archive", reason="Project paused: [reason]")`

### Re-Opening an Archived Project

If the user wants to resume work on an archived project:
- Read the archive documents to recover context
- Use `research_state(action="redirect")` to move back to the appropriate phase
- The archive documents remain as historical reference
- New work creates new objects (do not modify archived ones)

### Multiple Submissions from One Project

If the same research leads to multiple papers (e.g. main paper + workshop paper + journal extension):
- Each paper has its own `paper_XXX` and `sub_XXX` objects
- They share the same experiments, claims, and wiki
- Archive each submission cycle separately
- The project-level archive covers all submissions
