## Step 3: Define Contracts

### Sanity Contract

A minimal end-to-end test that runs in <5 minutes:

- Forward pass works
- Loss computes
- One optimization step runs
- Shapes are correct

### Quality Contract

Measurable thresholds the code must meet:

- Reproducibility: fixed seed → identical results
- Performance: baseline runs at expected speed
- Correctness: known input → expected output

## Step 6: Present to User and Advance

**⏸ CHECKPOINT — do not proceed without user input.**

**Checkpoint kind: `resource_commitment`**

Before transitioning to experiment phase, the user must confirm the code artifact is worth investing real compute resources.

Present:
- Code artifact summary (what was implemented, key modules)
- Sanity contract results (pass/fail, any warnings)
- Quality contract results (thresholds met or missed)
- Inspector review findings (critical/important issues fixed)
- Experiment matrix registered from plan
- Git commit hash for reproducibility
- Estimated compute budget for full experiment suite

**Options for user**:
1. **Approve and advance to experiment** — confirm resource commitment for full experiments
2. **Request code changes** — specific fixes or improvements before experiments
3. **Rollback to design** — implementation reveals design issues
4. **Reduce scope** — run subset of experiments due to budget constraints

Record user decision rationale in journal.
**In autonomous mode**: Agent may waive but MUST log waiver with reasoning to `phase_run.human_checkpoints`.

When a human checkpoint is triggered, the system auto-generates a checkpoint brief. The brief provides full context for the human decision. If you need to regenerate or view it, use `research_checkpoint_brief(action="generate"|"read")`.
